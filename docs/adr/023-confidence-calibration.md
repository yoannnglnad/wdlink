# ADR-023 — Confidence: softmax over candidates and NIL, temperature-scaled on dev

**Status:** accepted · **Evidence:** benchmark [`calibration`](../../eval/benchmarks/calibration.md).

## Context

The assignment's output has a "confidence" column, and the scores must be "generated by the implemented system". A raw score S is not a probability: S = 0.75 does not mean "right 75% of the time". The confidence should be one, so a user can set a review threshold on it.

## Options measured

In both variants the confidence is the softmax probability of the decision. The softmax runs over the candidates' scores plus a NIL option scored θ, so the confidence of a NIL decision is also defined. The temperature τ either stays fixed or is fitted by temperature scaling ([Guo et al., 2017](https://arxiv.org/abs/1706.04599)), i.e. set to the τ that minimises the negative log-likelihood of the gold option, on the training folds.

| Variant | CV accuracy | Mean confidence | ECE (5 bins) |
|---|---|---|---|
| fixed τ = 0.1 | 0.874 | 0.452 | 0.425 |
| **temperature scaling** (τ = 0.03 in all 5 folds) | 0.874 | **0.851** | **0.051** |

## Decision

Use temperature scaling, with τ fitted on dev.

## Why

- **A fixed temperature is badly under-confident.** It reports 0.45 on average for a system that is right 87% of the time.
- **After scaling, confidence and accuracy match.** The mean confidence is 0.85 for an accuracy of 0.87, and the expected calibration error falls from 0.43 to 0.05.
- **The fitted τ is stable.** It is 0.03 in all five folds.
- **Ranking and decisions are unchanged.** Temperature scaling has one parameter and leaves both untouched (identical accuracy).

On the first, 12-document dev split, the fitted τ sat at the edge of the grid (0.01), because only two dev mentions were wrong. The extended split, with hard NILs, has enough errors to fit the temperature properly. This is one reason the dev split was enlarged.

## Consequences

- Calibration only transfers to data that resembles dev. The final evaluation reports ECE on test and on KORE50. KORE50 is much harder, so the confidence is expected to be over-confident there, and the report says so.
- Re-calibrate (`wdlink eval` does so) whenever the target domain changes.
